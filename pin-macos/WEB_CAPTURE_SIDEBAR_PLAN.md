# Pin 网页采集侧边栏：低成本接入计划

> 给实现 AI 的任务计划；本文件不是开工授权，也不表示功能已完成。
>
> 产品目标：设计师在同一个 Pin 窗口里看素材网站，复制当前图片，点一次“放入画布”，图片进入本地素材库并立即出现在画布上。
>
> 证据起点：`Spikes/WebCaptureSpike/WEB_CAPTURE_SPIKE_REPORT.md`。花瓣多张成功；Pinterest、小红书各只有 1 张不同图片的粘贴成功记录。已证明跨站点的原生剪贴板机制可通，尚未证明每站的大样本稳定性、Pinterest 原图质量或侧栏窄宽体验。

## 1. 本轮只交付一个闭环

```text
左侧来源栏点“网页” → 侧边浮层内浏览网页 → 网页上复制图片
→ 点浮层“放入画布” → 沿用 Pin 现有粘贴导入流水线
→ 本地入库 + 当前画布出现图片 + 成功/失败回执 → 重启仍在
```

第一版只要求上述“两次动作”采集。用户在画布获得焦点时，原有 `⌘V` 继续有效；网页、地址栏获得焦点时，`⌘V` 留给网页/文字输入。侧栏按钮提供不依赖焦点的明确入口，不能通过全局抢占 `⌘V` 达成目标。

浏览器侧栏默认打开花瓣，提供 Pinterest 快捷入口和 `http(s)` 地址栏。它是**一个通用浏览器入口**，不是“花瓣专用解析器”。不在本轮承诺网页任意元素可采、所有网站可登录、所采必为原图。

## 2. 先冻结基线与分工

1. 开工前读取仓库 `AGENTS.md`、`GITHUB_MAINTENANCE_WORKFLOW.md`、本文件、Spike 报告，并记录当前分支、HEAD 与 `git status`。当前工作树已有大量未提交的 C1/C2 改动；本计划不把它们视为可覆盖的“旧版本”。
2. 与正在修改 `UI/`、`Materials/`、`App/` 的开发者确认一个稳定交接点；若同时编辑同一文件，先停止接入，改用独立工作区/明确文件归属。不得为集成而回退、覆盖或格式化他人的改动。
3. 所有自动测试使用 `dev-codex` 或临时 profile；人工验证可使用专用测试 profile。不得读写 DesignPeek、Pin Web 或用户正式 Pin 素材目录。
4. 本轮不提交、不推送、不打标签；是否同步 GitHub 由产品负责人另行确认。

## 3. 最小实现切片

### 切片 A：让网页住进现有来源面板

- 在 `Materials/MaterialSource.swift` 注册通用“网页”来源及 `.browser` 内容形态。若现有 `huaban` 来源标识尚无持久化依赖，可以改为稳定的 `web` 标识并更新相应自检；如发现依赖，保留旧标识并记录兼容理由，不做猜测式迁移。
- 在现有浮动面板位置显示 `WebBrowserPanel`，复用 Spike 的 `WebViewHost.swift` / 导航控制思路：一个 `WKWebView`、默认网站数据存储、后退/前进/刷新、地址栏、两个站点快捷入口。将 Spike 的代码按 Pin 的界面和生命周期改造；不把 Spike 的独立 App、日志面板、对照页和实验接收区搬进正式产品。
- 浏览会话由工作台长期持有；切到“截图”再切回“网页”时，当前页面、滚动位置与登录状态不应重置。正式 Pin 的 WebKit 数据容器与 Spike 不同，首次在 Pin 内登录需要用户自己完成，不复制 Spike Cookie。
- 浏览器面板使用独立于普通素材面板的宽度状态。普通素材面板目前上限 420 pt，而 Spike 浏览区要求至少约 520 pt；不能把网站硬塞进 200–420 pt 的列表宽度。先以约 520–600 pt 实测默认 1280 pt 窗口，并验证 960 pt 窄窗口不裁掉导航按钮、画布仍有可操作区；若真实网站在此宽度不可用，如实报告并停在布局决策，不靠强制缩放网页或叠第二窗口掩盖。
- 网页面板是浮层，画布尺寸/相机不因切换来源而重置；WebKit 只接收自己矩形内的事件，浮层外的画布平移、缩放、选择仍工作。

切片 A 完成条件：单窗口内花瓣、Pinterest 可导航；切换来源后返回仍是原页面；普通“截图”“字体”来源与画布交互无回归。网站登录结果单独记录，未测不得写“支持登录”。

### 切片 B：把已验证的剪贴板接到正式导入

- 网页面板只增加一个主按钮：**“将剪贴板图片放入画布”**。按钮调用 `WorkspaceModel.paste()`，沿用现有 `PasteboardReader → ImportCoordinator → AssetStore → BoardStore → ImportStatusToast`。图片应同时进本地素材库和当前画布，失败应显示现有回执。
- 不在 `WebBrowserPanel` 中新写存储、转码、缩略图或画布插入逻辑；不复制 Spike 的 `CaptureReceiver` 作为第二条正式导入流水线。若真实网站样本暴露现有 `PasteboardReader` 与 Spike 解析优先级不同造成失败，只在剪贴板读取层修正并补回归测试。
- 此入口本质上读取**系统当前剪贴板**，无法仅凭“用户在网页面板点了按钮”证明图片来自当前网站。因此本轮仍沿用 `.paste` 来源，不假标记为 `.web`，也不把当前页面 URL 写成该图片的来源证据。需要真实网页来源追溯时，再设计可验证的采集会话与数据字段。
- 采集成功后保留网页原位置，不自动切换来源；回执说明“已放入画布”。网页仍可继续浏览、连续采集下一张。空剪贴板、复制了文字、素材库未就绪、画布保存失败均给出可理解的提示。

切片 B 完成条件：在花瓣/Pinterest 各取至少 3 张不同图片跑“复制 → 点击按钮 → 画布出现 → 重启仍在”的人工冒烟；同时验证用户从 Finder/其他应用复制图片时，按钮不会错误宣称图片来自当前网页。

### 切片 C：按实测决定是否补拖拽

切片 B 的两次动作若已足够顺滑，**本轮到此停止**。只有人工试用明确认为拖拽是发布前必需，再追加以下小切片：

1. 从网页拖到画布：扩展画布现有的 `NSDraggingDestination`，让它除了文件 URL，还能接收 WebKit 提供的图片字节；把结果送进同一导入流水线，并按画布落点放置。
2. 从网页拖到素材面板：仅入库、不上画布，遵守现有面板落点语义。
3. 一次拖动只产生一张素材；字节、promised file、网页 URL 同时存在时，按经实测验证的优先级择一，且不能把“网页详情页 URL”误当图片 URL 下载。

拖拽不能仅把 Spike 的 `NativeCaptureDropView` 整块移植：它的目标是独立实验接收区，而 Pin 画布已有自己的拖拽事件、世界坐标落点和保存逻辑。若跨 `WKWebView`/画布的拖动被命中层或 WebKit 阻断，先保留切片 B 的可用产品路径，单独报告阻断，不增加站点专用 DOM 方案。

## 4. 明确不在本轮做

- 网页自动识图、悬停一键抓图、CSS 背景/Canvas/`blob:` 特殊采集；
- 批量抓取、整页扫描、站点私有接口、验证码/登录限制绕过；
- 多标签浏览器、下载管理器、浏览器扩展、与 Safari/Chrome 同步 Cookie；
- “网页采集”独立历史列表、页面 URL 持久化、素材去重、AI 分析；
- 大范围重构 `ImportCoordinator`、数据库 schema 或画布渲染器。

现有“截图”提供者读取的是全素材库，因此网页粘贴的图片目前也会出现在那里。这是**已有命名与实际内容不一致**，不是本轮再建一套网页图库的理由；将“截图”是否改称“素材库”，留给产品负责人单独确认。

## 5. 验证顺序与发布门槛

| 阶段 | 要看见的用户结果 | 最小验证 |
| --- | --- | --- |
| 界面接入 | 网站在侧边，画布仍可操作 | 默认窗与 960 pt 窄窗、切换来源、返回原页面、暗/亮色 |
| 采集接入 | 复制一张，点击后入库并出现在画布 | 花瓣 3 张、Pinterest 3 张、重启恢复、失败提示 |
| 回归 | 原有入口未损坏 | 文件选择器、Finder 拖入、画布 `⌘V`、截图面板与保存失败提示 |
| 对外宣称稳定支持某站 | 不只是“碰巧采到一张” | 该站至少 10 张预先确定的不同图片，成功至少 8 张；检查详情页、登录跨启动、图片质量与窄栏可用性 |

自动检查：正式 `pin-macos` 的 Debug / Release 构建和 `--selftest`；若修改剪贴板解析，增加图片字节/文件 URL/非图片/重复类型/大图拒绝等测试。真实站点的登录、页面质量和拖拽仍需人工实测，不能用无头测试替代。

验收报告必须分别写明：已验证的站点与样本数、图片是否为原图/裁切缩略图、操作步数、失败原因、窄窗口体验、普通来源和画布回归结果。Pinterest 现有 550×550 样本质量未确认，不能直接当作“原图采集通过”。

## 6. 预算与停止条件

- 估算：切片 A 约 1–2 开发日，切片 B 约 0.5–1 开发日，验证与修正约 0.5–1 日；总计约 **2–4 开发日**。这是基于现有 Spike 和 Pin 导入流水线的粗估，不含网站登录异常或跨视图拖拽攻关。切片 C 另估，不并入首轮承诺。
- 如果切片 A 在约 520–600 pt 内无法让目标网站稳定浏览，先请产品负责人决定侧栏宽度/窗口布局，再继续接采集。
- 如果切片 B 的正式导入在两个站点都反复失败，定位剪贴板载荷差异；只修共同读取路径。需要站点专用选择器、批量扫描或私有接口时停止并报告，不扩大本轮。
- 达到切片 B 的用户闭环后先交付试用，不因技术上“还可以做”而自动进入拖拽或高级采集。

## 7. 实现 AI 的交付格式

交付代码时提供：变更文件清单、基线提交和工作区状态、构建/自检结果、两站人工验证表、未测项、现有素材目录未受影响的证据，以及是否进入切片 C 的依据。按仓库维护流程更新本地 `VERSION_HISTORY.md`；未经用户明确确认，不提交、推送、合并、打标签或发布。
